# 数据安全与合规边界

Open Pharma Plugins 以本地运行和本地存储为主，但部分工具会将查询发送到公共 API 或已配置的搜索
提供商。用户仍需判断数据和用途是否符合所在司法辖区及组织政策。

## 本地存储

可变数据默认位于 `~/.open-pharma-plugins` 下：HCP 丰富化数据、培训内容和输出、活动简报与资源、
互动计划、区域方案，以及竞争情报观察列表、缓存和报告。支持 POSIX 权限时，目录使用 `0700`，文件
使用 `0600`。这些权限不能替代加密、备份、租户隔离、终端安全或企业访问控制。

导入 PDF、PPTX、CSV 或竞争情报源文件的工具可以读取 MCP 服务器进程有权访问的路径。应以最小文件
系统权限运行服务器，在批准前检查路径参数，并将无关敏感文件置于其可读范围之外。

## 外部传输

PubMed、ClinicalTrials.gov、ORCID、NIH RePORTER、openFDA、DailyMed 和所选 Web 搜索提供商会收到
请求所需的查询词。不要把凭据、机密策略、私有源文档或不必要的个人数据放入查询。提供商自身的条款和
保留政策仍然适用。

竞争情报缓存键、证据 URL、运行清单和报告清单会排除凭据类查询参数。API 凭据只保留在本地进程、配置和
传输请求中。

提供商 HTTP 错误在进入证据前会被安全清理。`ci_status` 只表示是否存在密钥，不代表密钥有效。
诊断失败来源时不得输出密钥。删除密钥时，应同时清除配置文件和优先级更高的环境变量，重启宿主并确认
状态，然后创建新的运行。

运行和报告目录不会覆盖旧文件，并通过哈希绑定，但不会自动过期或加密。哈希一致只能证明产物关联，
不能证明来源内容真实或已通过审核。

HCP 原始批量收集不会调用 LLM。为已打包的 `open-pharma-plugins-hcp-batch` 控制台添加
`--synthesize` 后，所选账户字段和全部已收集证据会发送到配置的 OpenRouter 兼容端点。合成业务数据
前，应确认端点、模型、提供商日志与保留条款，并取得组织批准。schema-v2 批处理清单会记录实际端点、
模型、reasoning effort 和请求超时，但不会记录 API 密钥。生成的账户 JSON、汇总 CSV 和清单可能包含
个人/公开来源数据；请保存在经批准的存储中，不要把本地文件权限当作企业访问控制。详见
[HCP 批处理](hcp_batch.md)。

打开 Territory Alignment HTML 地图时，会从公共网络加载带完整性校验的 Leaflet 资源以及
CARTO/OpenStreetMap 瓦片。瓦片提供商仍可观察网络和地图瓦片请求；若区域坐标不得发送给这些提供商，
请使用经批准的离线地图栈。

## 隐私、保留和药品内容

- 只处理明确目的所需的最少个人数据，并在持久化前确认 HCP 身份及来源。
- 执行计划前检查同意、退订、雇佣关系和区域规则。
- 默认目录不合适时，将各功能数据目录指向经批准的加密或托管存储。
- 项目不会自动过期业务记录；按组织保留政策删除功能目录、导出副本和备份。
- Campaign Studio 和 Field Training 的校验是防御层，不是审批。所有输出在分发或现场使用前必须由
  合格的医学、法务和监管人员审核。
- 内置声明、文档、账户、HCP、代表和竞品均为虚构样本，不得作为真实运营数据。

若凭据可能泄露，应在提供商处撤销凭据、清理相关缓存并执行组织的事件响应流程；删除本地文件不会
撤销凭据，也不会删除提供商日志。
